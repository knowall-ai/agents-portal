= Agents Portal Troubleshooting Guide
:toc: left
:icons: font

== Common Issues

[cols="2,3"]
|===
|Problem |Solution

|**"Sign in failed" after Microsoft login**
|Verify the redirect URI on the app registration matches exactly: `https://agents.knowall.ai/api/auth/callback/azure-ad` (or `http://localhost:3103/...`). Check `AZURE_AD_CLIENT_ID` and `AZURE_AD_CLIENT_SECRET`.

|**"Sign-in is not configured" on the login page**
|`AZURE_AD_CLIENT_ID` / `AZURE_AD_CLIENT_SECRET` are missing. Copy `.env.example` to `.env` and fill them in.

|**"Need admin approval" when signing in from a customer tenant**
|An admin in that tenant must consent once: `https://login.microsoftonline.com/common/adminconsent?client_id=<AZURE_AD_CLIENT_ID>`.

|**"Could not load agents from Azure" (ARM 403)**
|The signed-in user needs *Reader* on the agents' subscriptions or resource groups. Resource Graph only returns resources the user can read.

|**An agent is missing**
|Its resources have no `agent` / `project` tag and no registry entry claims the resource group. Tag them or add an entry to `config/agents.json` (see docs/ONBOARDING.adoc). Remember tags on a resource group are not inherited by resources.

|**Customer agent not visible from the KnowAll tenant**
|Lighthouse delegation is missing or grants the wrong principal. Run `az managedservices assignment list` in the customer subscription. The delegated group must include the signed-in user.

|**Agent shows Degraded although the VM is running**
|The reachability probe to `healthUrl` / `portalUrl` failed. Check the URL answers from the internet (a `302` to sign-in is fine). Remove `healthUrl` if the portal is intentionally private.

|**Skills list is empty for an OpenClaw agent**
|Set `repo` and `skillsPath` in `config/agents.json`. For private repos set `GITHUB_TOKEN` on the server. Check the server log for `GitHub 404`.

|**Plugin / shared skills (T-Minus-15, KnowAll AI) missing for an OpenClaw agent**
|The portal only reads the repos in the registry. Add each shared skill pack to `skillSources` in `config/agents.json` (e.g. `knowall-ai/claude-plugins` and `T-Minus-15/claude-plugins`, path `skills`) and make sure `GITHUB_TOKEN` has Contents: read on them — `knowall-ai/claude-plugins` is private.

|**SOUL.md section missing on an agent page**
|The agent needs `repo` in the registry and a `workspace/SOUL.md` or `SOUL.md` in that repo (or `soulPath` set). Check the server log for `GitHub 404`.

|**Licences card says User.Read.All is not consented**
|Reading another user's licences needs the *User.Read.All* delegated Graph permission on the app registration with admin consent (see the README setup step). After granting it, sign out and in again so the refresh token carries the new scope.

|**Permissions card says Directory.Read.All is not consented**
|The *Directory.Read.All* delegated Graph permission (admin consent) is needed to read groups, directory roles, app registrations and consent grants. Grant it as in the README setup step, then sign out and in again.

|**No AI Foundry assistants shown**
|The token exchange for `https://ai.azure.com/.default` failed — the app registration needs the *Azure Machine Learning Services / user_impersonation* delegated permission with admin consent, and the user needs *Azure AI User* on the AI Services account.

|**Activity feed is empty**
|The Azure Activity Log only keeps 90 days and the dashboard shows 7. Only Succeeded/Failed events are listed. GitHub commits need `repo` in the registry.

|**Tenant switcher shows only one tenant**
|`GET https://management.azure.com/tenants` lists tenants where the user has an account (member or guest). Invite the user as a guest to the customer tenant first.

|**Stale data after fixing something in Azure**
|Results are cached for `CACHE_TTL_SECONDS` (default 60). Wait a minute or restart the app.

|**Dev server errors after switching branches**
|`rm -rf .next && bun run dev`.

|**Agent shows Not responding although the portal URL works in a browser**
|The probe only follows `https` URLs whose host resolves to a public address. `http://` URLs, `localhost`, `*.local`/`*.internal` names and private IP ranges are refused deliberately. Use the public `https` hostname.

|**"Chat in Teams" is missing for an agent**
|Set `teamsUpn` in `config/agents.json` for agents with their own Entra account. Bots need a Bot Service resource in a subscription you can read; the link uses its Microsoft App ID.

|**Avatar shows initials instead of the image**
|`avatarUrl` must be a path under `public/` (e.g. `/agents/sallie.png`) or an `https` URL. Check the file exists and the browser network tab for a 404.

|**`az webapp create` fails with "Linux Runtime 'NODE\|20-lts' is not supported"**
|App Service has retired Node 20 for new sites. Use `--runtime "NODE:22-lts"` (`az webapp list-runtimes --os-type linux` lists what is available).

|**`az webapp config ssl create` fails with "Missing one DNS record"**
|Either the CNAME has not propagated yet (wait a few minutes and re-run) or it was added to the wrong DNS. `knowall.ai` is served by Microsoft 365 DNS, not the Azure DNS zone — add records in the Microsoft 365 admin center. Check with `dig +short agents.knowall.ai`.

|**Cost tile shows "n/a" or the breakdown says "Azure: lookup failed"**
|Either the user lacks *Cost Management Reader* on the subscription, or Cost Management returned 429. Cost Management throttles *third-party client apps* to roughly one query every 25–40 seconds per subscription (headers `x-ms-ratelimit-microsoft.costmanagement-clienttype-retry-after` / `entity-retry-after`), even though the Azure CLI, a first-party client, is not throttled. The dashboard serialises its queries, honours those headers with up to three retries, caches results for 30 minutes and caches a failure for 2 minutes. The first load after a restart can take up to a minute; after that it is instant. Check the server log for the `429 from management.azure.com; waiting …` lines.

|**Costs are missing for OpenAI / Anthropic**
|"not configured" means `OPENAI_ADMIN_KEY` / `ANTHROPIC_ADMIN_KEY` is unset on the server; "not linked to this agent" means the registry entry has no `openaiProjectId` / `anthropicWorkspaceId`. Spend under the ChatGPT subscription is not in any API — add it as a `fixedCosts` line.

|**Cost figures look low for today**
|Azure Cost Management lags usage by up to 24 hours, and month-to-date resets on the 1st (UTC).

|**Production deploy workflow fails at "Login to Azure"**
|The `AZURE_CREDENTIALS` secret must be the JSON from `az ad sp create-for-rbac --sdk-auth` for a principal with Contributor on the App Service. Re-create it and set the secret again with `gh secret set AZURE_CREDENTIALS -R knowall-ai/agents-portal`.
|===
