== Overview

Agents Portal deploys to Azure App Service as a Next.js standalone build, the same way as ZapDesk. Pushing a `v*` tag runs `.github/workflows/deploy.yml`.

[cols="1,2"]
|===
|Item |Value

|App Service
|`agent-dashboard-knowallai` (Linux, Node 22 LTS, `devdesk-plan` B1 in KnowAllAIRG — same plan as ZapDesk)

|Production URL
|https://agents.knowall.ai

|Local port
|3103 (Thyme uses 3101, ZapDesk 3102)
|===

== One-time setup

=== 1. Entra app registration

Follow the *Entra ID App Registration* section in the README. Add the production redirect URI `https://agents.knowall.ai/api/auth/callback/azure-ad`.

=== 2. App Service

[source,bash]
----
az webapp create -g KnowAllAIRG -p devdesk-plan -n agent-dashboard-knowallai --runtime "NODE:22-lts" --https-only true
az webapp config set -g KnowAllAIRG -n agent-dashboard-knowallai --startup-file "node server.js" \
  --min-tls-version 1.2 --ftps-state Disabled --http20-enabled true \
  --generic-configurations '{"healthCheckPath": "/api/health"}'
----

Runtime settings live in App Service configuration (the deploy workflow does not touch them):

[source,bash]
----
az webapp config appsettings set -g KnowAllAIRG -n agent-dashboard-knowallai --settings \
  NEXTAUTH_URL=https://agents.knowall.ai APP_URL=https://agents.knowall.ai \
  NEXTAUTH_SECRET=$(openssl rand -hex 32) \
  AZURE_AD_TENANT_ID=common AZURE_AD_CLIENT_ID=<app-id> AZURE_AD_CLIENT_SECRET=<production-secret> \
  GITHUB_TOKEN=<github-token> \
  SCM_DO_BUILD_DURING_DEPLOYMENT=false WEBSITE_HEALTHCHECK_MAXPINGFAILURES=5 CACHE_TTL_SECONDS=60
----

The app registration needs the delegated Graph permissions *User.Read.All* (Licences card) and *Directory.Read.All* (Permissions card), both with admin consent; the README setup command includes it.

`GITHUB_TOKEN` is a fine-grained token with *Contents: read* on every agent repo and on the shared skill-pack repos listed in `skillSources` (`knowall-ai/claude-plugins` is private).

=== 3. Custom domain and TLS

IMPORTANT: `knowall.ai` is delegated to Microsoft 365's name servers (`ns1-4.bdm.microsoftonline.com`), so DNS records are managed in the **Microsoft 365 admin center → Settings → Domains → knowall.ai → DNS records**. The Azure DNS zone `knowall.ai` in `knowallairg` is *not* authoritative; records added there have no effect.

. Get the verification ID:
+
[source,bash]
----
az webapp show -g KnowAllAIRG -n agent-dashboard-knowallai --query customDomainVerificationId -o tsv
----
. In the Microsoft 365 admin center add two records:
+
[cols="1,2,3"]
|===
|Type |Name |Value

|TXT
|`asuid.agents`
|the verification ID above

|CNAME
|`agents`
|`agent-dashboard-knowallai.azurewebsites.net`
|===
. Bind the hostname and issue the free managed certificate (retry the `ssl create` if it reports a missing DNS record — propagation takes a few minutes):
+
[source,bash]
----
az webapp config hostname add -g KnowAllAIRG --webapp-name agent-dashboard-knowallai --hostname agents.knowall.ai
THUMB=$(az webapp config ssl create -g KnowAllAIRG -n agent-dashboard-knowallai --hostname agents.knowall.ai --query thumbprint -o tsv)
az webapp config ssl bind -g KnowAllAIRG -n agent-dashboard-knowallai --certificate-thumbprint "$THUMB" --ssl-type SNI
----

The App Service managed certificate renews itself.

=== 4. GitHub secrets

[cols="1,2"]
|===
|Secret |Value

|`AZURE_CREDENTIALS`
|Service principal `agent-dashboard-github-deploy` with Contributor scoped to the App Service only. Created with `az ad sp create-for-rbac --sdk-auth` and piped straight into `gh secret set` so the value is never displayed.

|`ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`
|Optional — used by the manual *Claude Code Review* workflow
|===

=== 5. Branch protection

`main` mirrors ZapDesk and Thyme: required checks *Lint*, *Format*, *Type Check*, *Unit Tests*, *Build* and *Title, body and issue link*; one approving review with code-owner review; stale reviews dismissed; no force pushes. A ruleset requests a Copilot review on every PR.

== Releasing

[source,bash]
----
bun run check
bun pm version patch    # or minor / major — updates package.json and tags
git push --follow-tags  # tag triggers the deploy workflow
----

The version appears in the sidebar footer.

== Manual first deployment

The workflow deploys on tags. To push a build by hand (e.g. the very first deployment):

[source,bash]
----
bun run build
cp -r public .next/standalone/ && cp -r .next/static .next/standalone/.next/
(cd .next/standalone && zip -qr ../../deploy.zip .)
az webapp deploy -g KnowAllAIRG -n agent-dashboard-knowallai --src-path .next/deploy.zip --type zip
curl https://agents.knowall.ai/api/health
----

== Environment Variables

See `.env.example`. Runtime settings are App Service application settings; the deploy workflow only builds and ships the standalone bundle.
